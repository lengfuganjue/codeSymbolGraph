# CSG 场景覆盖分析 & 改进路线图

> 面向 Unity + XLua 项目，分析 Claude Code 代码导航的所有使用场景，
> 对比 Grep / LSP（csharp-ls + LuaLS）/ CSG 三种工具的支持情况，
> 并标注 CSG 的改进优先级。

## 图例

| 标记 | 含义 |
|------|------|
| ✓ | 完整支持，结果可靠 |
| △ | 部分支持，需人工辅助或结果不稳定 |
| ✗ | 不支持 |
| **✓ 可实现** | CSG 当前不支持，但技术上可实现，标注优先级 |

## 三、跨语言（C# ↔ Lua）——CSG 独有核心价值

| 场景 | Grep | LSP | CSG 现状 | CSG 可达 | 优先级 |
|------|:----:|:---:|:-------:|:-------:|:------:|
| 找 Lua 中 `CS.Type:Method()` 直接调用 | △ 需知道命名空间 | ✗ | ✓ | ✓ | — |
| 通过别名链找 Lua 调用（`C_Helper:Do()`） | ✗ 别名不透明 | ✗ | ✓ | ✓ | — |
| 通过 GetComponent 动态绑定找调用 | △ 方法名 grep | ✗ | △ grep 兜底 | △→✓ | P1 |
| 某 C# 类被哪些 Lua 文件使用 | △ 需搜所有别名 | ✗ | △ | **✓ 可实现** | P1 |
| 某 Lua 文件依赖哪些 C# 类型 | △ 搜 `CS\.` | ✗ | ✗ | **✓ 可实现** | P1 |
| XLua 别名链完整解析 | ✗ | ✗ | ✓ | ✓ | — |
| 热更新（Hotfix）覆盖哪些 C# 方法 | △ 搜 HotFix 属性 | ✗ | ✗ | △ | P2 |
| XLua Gen 注册文件 ↔ 原始类映射 | △ | ✗ | △ 被过滤 | △ | P2 |

### 实现思路
- **C# 类被哪些 Lua 文件使用**：查 `xlua_mappings` + `lua_aliases` 表，按 `csharp_fqn LIKE` 聚合。
- **Lua 文件依赖哪些 C# 类型**：查 `xlua_mappings WHERE lua_file = ?`，提取 `csharp_fqn`。
- **GetComponent 短名解析**：`workspaceSymbol(shortName)` 找唯一匹配，解析 FQN。

## 四、调用链分析

| 场景 | Grep | LSP | CSG 现状 | CSG 可达 | 优先级 |
|------|:----:|:---:|:-------:|:-------:|:------:|
| C# 方法 incoming 调用链（多层） | ✗ 只有文本 | △ 虚方法遗漏 | △ | △ | — |
| C# 方法 outgoing 调用链 | ✗ | ✓ 协议支持 | ✓ 已接入 | ✓ | ~~P0~~ 已完成 |
| Lua 函数 incoming 调用链 | ✗ | △ LuaLS | △ | △ | — |
| Lua 函数 outgoing 调用链 | ✗ | △ LuaLS | ✗ | △ | P2 |
| 跨语言完整链路（Lua→C#→Lua） | ✗ | ✗ | △ 仅1层 | △ | P2 |
| 从 A 到 B 的调用路径 | ✗ | ✗ | ✗ | ✗ | — |
| 循环依赖检测 | ✗ | ✗ | ✗ | △ | P3 |

### 实现思路
- **outgoing 调用链**：`lsp-client.ts` 已实现 `callHierarchyOutgoing()`，
  直接在 `findCallChain` 中接入，与 incoming 逻辑对称。
- **跨语言链路**：outgoing 结果中的 C# 方法，再查 `xlua_mappings` 找 Lua 调用点，拼接为完整链路。

## 五、影响分析（重构 / 修改安全性）

| 场景 | Grep | LSP | CSG 现状 | CSG 可达 | 优先级 |
|------|:----:|:---:|:-------:|:-------:|:------:|
| 修改 C# 方法签名影响哪些文件 | △ | △ | ✓ | ✓ | — |
| 修改 C# 类影响哪些 Lua 文件 | ✗ | ✗ | ✓ | ✓ | — |
| 删除方法是否安全（无引用） | △ | △ | △ | △ | — |
| 重命名方法的所有改动点预览 | △ | △ | △ | **✓ 可实现** | P1 |
| 跨语言重命名（C# → Lua 别名失效） | ✗ | ✗ | ✗ | △ | P2 |
| 接口方法修改影响所有实现类 | △ | ✗ | ✗ | **✓ 可实现** | P1 |

### 实现思路
- **重命名预览**：新增 `csg_rename_preview` 工具，
  组合 `findReferences` + `queryCrossLang` + Lua alias 扫描，
  返回分类后的"必须修改"和"可能受影响"列表。
- **接口实现影响**：依赖 `csg_hierarchy` 先找所有实现类，再对每个实现类查 references。

## Grep / LSP / CSG 能力边界总结

```
Grep      → 文本搜索无敌，但无语义，无法跨语言，结果含噪
LSP       → 单语言语义精准，但不跨语言，虚方法存在盲区
CSG 现状  → 跨语言核心能力 + 继承树 + outgoing链（已完成），文件依赖待实现
CSG 目标  → 覆盖所有"需要理解代码结构"的场景，与 grep 互补
```

**分水岭**：凡是需要"理解代码结构"而不是"找文本"的场景，都应该是 CSG 的主场。
